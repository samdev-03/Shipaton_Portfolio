# Icons, screenshots and video

The four `assets/brands/<variant>/icon.png` files are original, opaque 1024 × 1024 icons. Their SVG sources are editable; `npm run assets` regenerates them and Android adaptive foregrounds. Verify store mask/safe-area appearance in the signed binary. Typography files and license notices are bundled in the project.

`artifacts/screenshots` contains eight actual 1179 × 2556 web-preview captures from the automated workflows. They show fictional examples and are provided for design review. Although their pixel dimensions match the event specification, **they are not native-device evidence and must not be submitted as such**.

| App | First native screenshot to capture | Additional store sequence |
| --- | --- | --- |
| Rehearsal | A practice response with the retry opportunity and supportive cue | Scenario home; revised response; saved reflection; actual localized Pro offering |
| Care | An acknowledged task and visible member assignment | Private circle; invitation; handoff awaiting acceptance; completed task |
| Meal | Meal additions with selected constraints | Ingredient/step detail; saved meals; actual weekly plan with Pro |
| Quote | Itemized quote showing scope and totals | Public customer review; accepted status; template; actual Pro offering |

Use a real supported device at 1179 × 2556 for the required hackathon screenshot, without a decorative device frame. Use the store's current accepted resolutions for its own listing slots. Do not stretch a smaller screenshot, conceal an error, fabricate a paid offering, paste in a push receipt or present a web capture as native. Keep status-bar/device details truthful. Consent to all visible participant data; fictional examples are simpler.

Record the intended native device workflow with the matching script in `docs/submission/DEMO-SCRIPTS.md`. Every script fits below two minutes with rehearsed actions. Capture the app and narrate what it does; include genuine sponsor behavior only after device/account verification. Save an uncut original, make only honest editorial trims, and add readable captions. Do not use unlicensed music or influencer likenesses. Check that the final duration is strictly below 120 seconds and the YouTube/Vimeo link is public or otherwise directly accessible to judges as the rules require.

At capture time, disable unrelated personal notifications, use fictional account content, and avoid recording credentials, recovery codes, quote tokens outside the intended demo, or private dashboards. A screenshot of the configured integration is supporting evidence; it is not proof of delivery, revenue or user impact.

Keep original device captures and private receipts outside the source archive in `private-evidence`. Record shareable locations in the evidence ledger only after checking access. That directory is excluded from both git and the packaging script.
